01 — The Method

The Heuristic Evaluation Guide

Copy decisions used to come down to opinion: one person's "this reads better" against another's. I built a seven-point heuristic evaluation guide, drawn mainly from NN/g and Podmajersky, that turns those judgments into a shared, repeatable diagnosis.
Every string is checked against the same criteria: clarity, actionability, context fit, findability, conciseness, consistency, and tone fit.

Each issue gets a severity rating.

For the team, that moved copy from a subjective, last-minute polish into a diagnostic step where every change carries a stated reason and a priority.
And because the same problem categories kept surfacing, the guide doubled as a map of what to standardize: the recurring issues are where our reusable text patterns came from.

02 — The System

The Content Style Guide

Alongside the evaluation guide, I created the product's first content style guide: a single source of truth for voice, tone, terminology, formatting, and the copy patterns that grew out of the heuristic work. Before it existed, there was no central reference, so voice drifted between features and one concept could appear under several different names depending on who wrote it.

Now writers, designers, PMs, and engineers can write against the same vocabulary. Reviews move faster, new contributors get up to speed sooner, and localization has the stable source terminology it needs to stay predictable and affordable across languages.

Localization & Tooling

Localization is where content design meets engineering, and it's where I rebuilt the workflow so it could scale without magnifying the manual effort behind it.
Working in PowerShell on Windows, I set up the Phrase CLI with a per-project config pattern that pulls and pushes content across many projects in a single command, plus a Python audit script that compares every language against the English source across all 13 projects, flags the gaps, and exports a reviewable report.

On top of that sits a repeatable batch pipeline: pull, review, translate, generate push-ready files per language, push, then re-audit to confirm.
The scripted approach makes bulk operations trivial: I expanded the entire product to eight languages by creating 65 new locales in a single run, and can roll terminology or pattern fixes across every locale at once instead of editing file by file.
The same tooling enforces consistency at scale, scanning pulled content for term-base violations, or for the same English string translated differently across projects, which is nearly impossible to catch by hand or even within the Phrase software.

The audit doubles as a developer handoff tool. Because it treats the English source as the source of truth, it surfaces source-side bugs (broken template syntax, stray characters, fragmented strings) and turns them into a structured list for engineering and PM, so issues get fixed at the root instead of silently propagating into every translation.
The result is a L10N process that's faster, auditable, and far less dependent on manual repetition.
